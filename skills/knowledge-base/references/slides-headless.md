#### Headless mode (`kb slides <path> headless`)

**Where this file's cross-references resolve.** This file holds Mode 5's headless overrides; `SKILL.md` and `references/slides.md` are read first. "Steps 1 to 5" and "Step 5 above" below are Mode 5's steps in `references/slides.md`. Override 2's "Mode 1 (Process Inbox) deep-read, summary, and auto-file flow" is in `references/inbox.md`: read it at that point and run it on the given path. The helper commands are defined under `## Helper commands` in `SKILL.md`.

Invoked unattended by a scheduled slide queue of your own or by any `claude -p` caller. The trigger is the token `headless` (or `mode=headless`) anywhere in the invocation. It produces the same outcome as the interactive flow (the item filed into its best-fit topic folder, the deck built, everything filed and searchable), with every decision auto-resolved and no pauses. Apply these overrides to Steps 1 to 5:

1. **Target is always a resolved path.** The caller passes an absolute file path, never a name fragment. Skip the Step 1 name-fragment search and its multi-hit picker entirely; use the path directly.

2. **File the item from wherever it sits.** Do not require the source to be in `aa-inbox/`. A drop-queue path such as `aa-slides-inbox/_processing/<stamp>-<name>/<file>` matches none of the Step 2 cases. Override Step 2: run the Mode 1 (Process Inbox) deep-read, summary, and auto-file flow on the given path **regardless of its location** (process it as a single item, in its own subagent as Mode 1 requires), then fall through to Case B with the new in-topic path. Auto-file into the single best-fit topic folder with no confirmation (the overflow folder if no clear fit, noted in the result line), unless override 3's duplicate check applies, in which case do not file. Skip the user-facing batch-summary and rate-usage reports; they would go only to the discarded run log.

3. **Probable duplicate: do not process, leave for review.** Before launching the deep-read agent, run the scripted duplicate check on the dropped filename stem: `kb-dup-check "<stem>" [--url <url>]`. Act on its exit code, deterministically: `DUP` (exit 1) means stop without the deep read or the build; `NEAR` (exit 2) and `ERROR` (exit 3, the check could not complete: fail closed, since an unattended duplicate filing plus an overnight deck build is the expensive error) both mean skip-and-defer, do not file, do not build. Only `OK` (exit 0) proceeds. If a duplicate instead becomes apparent only during the deep-read and auto-file step, still abort filing and the deck build at that point. In every `DUP` case write the result sentinel `DUP <existing entry>` as the final action and leave the source file exactly where it sits (do not move, rename, file it, or write `_text.md` or `_summary.md` beside it); the queue script returns it to the drop folder for review. A `NEAR` or `ERROR` deferral likewise leaves the file untouched, with the check's output line as the result.

4. **The split is NOT retained; the reading agent has already deleted it.** (This item once said the opposite and instructed that the split be kept at `<topic>/<stem>/<stem>_build/split_<name>/`, contradicting `references/inbox.md` Step 4a and `references/slides.md`, which both delete it. It was stale rather than an override: this flow runs the Mode 1 flow, so the deletion happens inside the reading agent, before anything here could act.) The retained `<stem>_text.md` in the item folder is what lets the next step skip re-splitting, and that was always true. (Non-PDF sources have no split.)

5. **Existing-slides default is skip.** If a deck already exists for the item (a re-run), skip the build without rebuilding and do not pause; report `OK <existing deck path> (already built)`. Never back up or clobber a deck that may have been hand-edited.

6. **Hand off to your unattended slides entry point, not to the Beamer workflow.** Replace the Step 4 handoff with `Skill(skill="<your unattended slides entry point>", args="<absolute post-rename in-topic source path>")`. Passing the **renamed in-topic path** (not the original dropped name) is what makes that entry point find `<stem>_text.md` and reuse it, skipping the expensive re-deep-read instead of re-splitting from scratch. The entry point hands the path to your deck generator at its deep-read tier and auto-resolves every decision point, so every generator standard flows through unchanged. **The deliverable is `<stem>_slides.pptx`, a native editable deck, with a `<stem>_slides.pdf` review render beside it. The run writes no `.tex` and compiles nothing**, so a headless host needs no TeX installation. **`plan=` is a terminal refusal on this path**, never a silent drop: this handoff forwards nothing and the unattended entry point accepts no plan argument, so a forwarded token would vanish and the deck would build as though no plan existed. Refuse with `Refused: plan= is not accepted on the headless path, which forwards nothing. Drop the headless token to build the plan interactively, or drop plan= to build headless from the source alone.` Forwarding a plan here is a capability nobody has asked for yet rather than an impossibility, and adding it is a decision, not a repair.

7. **Post-build sync.** Run Step 5 above (the index-update hook plus the recents and full-text refresh) as normal.

The interactive flow in Steps 1 to 5 is unchanged; this subsection applies only when `headless` is present.
